# IDEA 审阅操作对照清单

按一次 agent 改动后最常用的顺序排列。用包含已修改、未跟踪和部分暂存文件的测试仓库逐条对照。涉及快捷键的步骤使用 macOS 键位。

| 优先级 | 场景 | 验收步骤与预期 |
| --- | --- | --- |
| 1 | Commit 变更树复制 | 在 Unversioned Files 选中 `README.md`，`⌘C` 粘贴得到 `~/Projects/demo/docs/README.md`。主目录外保留绝对路径。已跟踪的变更行复制文件名。选中的行与提交勾选框各自独立。 |
| 2 | Project 文件树复制和打开 | 单击文件或目录只选中，`⌘C` 得到名称。双击或按 `Enter` 打开文件，目录箭头展开。编辑器取得焦点后，`⌘C` 复制所选文字。 |
| 3 | 从 Commit 打开差异 | 选中文件后按 `⌘D` 或双击打开 Diff。关闭 Diff 后原文件仍选中。单击是否预览按 IDEA 的对应选项分别验收。 |
| 4 | 连续看差异块和文件 | `F7` / `⇧F7` 导航差异块。到文件边界时先提示，再按一次进入下一文件首个或上一文件末个差异。`⌥←` / `⌥→` 直接切换 Diff 文件。 |
| 5 | 跳源码和往返 | 在 Diff 指定一行按 `F4`，源码定位到对应行列。`⌘[` 回到该 Diff，`⌘]` 再到源码。 |
| 6 | 明确复制路径格式 | 在树中按 `⌘⇧C` 复制选中项的绝对路径。右键「复制路径／引用」分别检查文件名、绝对路径、项目相对路径和仓库相对路径。 |
| 7 | 在 Project 中定位 | 从源码或 Diff 按 `⌥F1`，在「Select In」入口选择 Project，展开祖先目录、选中目标并滚动到可见位置。 |
| 8 | 按文件和行列定位 | `⌘⇧O` 搜索文件名或路径，粘贴 `~/.../README.md:12:3` 后回车定位。源码中 `⌘L` 打开行列跳转。 |
| 9 | 文件内查找和轻改 | 在源码用 `⌘F` 查找，`⌘G` / `⇧⌘G` 前后找匹配，`⌘R` 进行替换，`⌘Z` 撤销，`⌘S` 保存。Diff 查找作用于当前侧。 |
| 10 | 打开常用工具窗口 | `⌘0` 打开并聚焦 Commit，`⌘1` 打开并聚焦 Project。切换工具窗口时当前编辑器保持原位置。 |
| 11 | 看改动的归属 | 在双栏工作区 Diff 悬停已提交的基准行和本地修改行，分别显示作者、时间及提交主题和「未提交的本地修改」。在单栏提交 Diff 分别悬停删除行和新增行，归属来自对应的父提交和当前提交。滚动后提示立即消失，重新悬停后以当前行取值。 |
| 12 | Git 记录视图选项 | 提交列表的小眼睛控制作者、日期、哈希和引用显示。变更文件的小眼睛控制目录分组、差异预览和文件历史范围。用不同目录下的同名文件确认显示、选择和打开 Diff 对应同一个文件。将窗口缩到 640 点宽，确认提交主题可见，两个小眼睛可操作。关闭提交详情，悬停在被省略的主题上，核对完整主题和提交哈希，移开鼠标后提示收起。放宽窗口后核对选中的文件和列选项。 |
| 13 | 文件历史范围和 Diff 导航 | 在文件历史中显示全部受影响的文件，选中另一个文件，然后恢复文件历史范围，确认「查看差异」回到当前可见的文件。在预览关闭时从 Git 记录选中另一条提交，已打开的 Diff 继续浏览原提交内的文件。 |
| 14 | Project 滚动到选中项 | 用多于一屏的文件树启用「始终选中打开的文件」，通过文件搜索打开末尾文件，确认树跟随并保留编辑器焦点。聚焦文件树后用上下键继续移动，确认选中项在可视区域。 |
| 15 | Commit 与 Git 记录的长列表 | 用多于一屏的变更和提交测试上下键。列表应滚到选中项，复制文件名和打开 Diff 应作用于同一行。 |
| 16 | 源码 Git Blame | 对一个包含可折叠代码块的长文件显示整文件 Git Blame。折叠后仅给可见行显示归属，展开后恢复。滚轮移动后确认归属和行号同步，悬停显示作者、时间和提交主题。Agent 新建文件的行标为「未提交的本地修改」。 |
| 17 | 多仓工作树 | 在两个仓库中创建同名分支。从第二个仓库菜单创建带空格和中文路径的工作树，确认文件来自第二个仓库。检查锁定显示、普通移除对未提交文件的保护、移除后分支仍存在，以及从菜单打开工作树后可浏览其中的改动。 |
| 18 | 切换工作区与后台刷新 | 延迟前一个工作区的工作树查询，在查询返回前切到另一个工作区。旧查询返回后，当前界面仍显示新工作区，旧仓库菜单保持关闭。在整仓刷新期间同时触发文件监听，确认隐藏仓库的操作和各仓库的文件变化都生效。 |
| 19 | 语言服务审阅 | 用真实 clangd 打开合成 C 仓库。光标留在错误行时，右键另一个符号查看文档并跳到头文件声明。声明前有 emoji，跳转应对准符号。从问题列表跳回错误行，用 `⌥F7` 查找引用。确认格式化后可撤销，磁盘内容在保存前保持原样。另用受控服务验证 `⌥↩` 打开快速修复并可取消。 |
| 20 | 源码分栏的右键操作 | 左右栏打开两个不同文件。焦点留在左栏，在右栏右键选择查看文件历史。确认打开的是右栏文件的历史，关闭后仍可继续操作分栏。 |
| 21 | 从指定文件解决冲突 | 在两个文件同时发生真实合并冲突时，从 Commit 列表和 Diff 打开第二个文件。取来源并保存后，检查工作区和 Git 暂存区，确认第一个文件仍处于冲突状态。 |
| 22 | 继续合并与变基 | 全部解决后继续合并，模拟 Git 提交钩子拒绝一次，确认可在工作台重试，并核对合并提交的两条父链。让变基连续停在两条提交，解决第一处并继续后应自动显示第二处，结束后核对分支和两条提交的内容。 |
| 23 | 隔离合并的恢复与重试 | 从分支矩阵开始合并，关闭并重新打开待处理的隔离任务。解决冲突后，主工作树里保留未跟踪文件并尝试完成合并。目标分支应保持原样。清理该合成文件后重试，核对合并提交、文件内容和隔离工作树清理。 |
| 24 | 同名仓库与同名文件 | 在 `mani.yaml` 中给一个仓库设置与另一个目录相同的名字，两仓均放入 `review.txt`。从 Commit 打开 Diff、暂存，从源码保存并在分支矩阵新建分支。每步用 Git 和文件内容核对目标。隐藏其中一个，临时移走目录并重启。从已保存的路径恢复后再移回目录，确认两个仓库仍使用各自的标识。 |
| 25 | 多仓库的 Git 记录与 PR / CI | 在 Git 记录选中子仓库的提交，从工具栏打开 PR / CI，确认列表来自该仓库。将 Git 记录筛选到另一仓库，确认右侧文件随可见提交更新。打开正文超过一屏的 PR，应当直接看到 CI 状态并能向下继续阅读。打开评论后改写 `origin`，确认提交被拦下且内容可重试。恢复 `origin` 后用替身核对评论、草稿 PR 的目标，创建成功后确认列表刷新。 |
| 26 | PR 提交与请求取消 | 用替身接收评论并延迟回执，检查重复提交、切换仓库和关闭面板在提交期间均不可用。回执成功但详情刷新失败时，仍显示「评论已发送」。单独取消列表读取，确认可以继续操作。模拟草稿创建的结果无法确认，检查原草稿保留，并提示先核对远端再重试。 |
| 27 | 审阅历史与未保存编辑 | 在两个工作区 Diff 间按 `⌘[` 和 `⌘]` 跳转。当前文件有未保存编辑时，使用与普通切换相同的受检保存。Agent 同时写盘时，保留编辑、历史位置和磁盘内容，确认磁盘版本后可再次跳转。过期的 Diff 位置应跳过。两个已提交文件的 Diff 也应能前后跳转。 |
| 28 | Agent 提交、权限变化和改名 | 打开未跟踪文件的 Diff，外部提交该文件后查看差异计数归零。只修改权限时，源码和工作区 Diff 随之更新可编辑状态。暂存改名并继续编辑新文件，分别核对暂存区里的旧路径，以及未暂存比较所用的新路径。 |
| 29 | 后台刷新与界面响应 | 用合成仓库暂停 Git 对已打开 Diff 的读取，确认仍能切换 Project 侧栏并在 Diff 中录入。释放请求后，新比较基准和未保存编辑同时保留。连续触发两次刷新，再让较早的结果最后返回，确认源码和 Diff 都保持较新的版本。 |
| 30 | 整文件暂存与取消暂存 | 暂停快捷键暂存或右键取消暂存所触发的 Git 命令，确认仍可选择别的文件和切换侧栏。核对索引只改变原目标，索引锁导致失败后可重试。暂存 `report[1].txt` 时保留 `report1.txt` 的原状态。取消暂存改名时同时更新旧路径和新路径，磁盘文件保持原样。 |
| 31 | 后台打开提交 Diff | 暂停读取下一文件的 Git 对象，再从记录打开第三个文件。第三个文件应先打开并跳到改动处，恢复慢请求后仍保留第三个文件。另选提交，再暂停原提交的变更文件列表读取，此时切到源码应继续停留在源码。重新切回 Diff 后仍可在原提交的文件间导航。 |
| 32 | 返回 Diff 时保留阅读位置 | 单栏提交 Diff 定位到百行后的变更，切到源码再切回，原变更仍可见。双栏工作区 Diff 将两侧滚到不同位置，切往源码或打开另一个 Diff 后返回，两侧分别恢复各自的滚动位置。 |
| 33 | 后台打开和预览工作区 Diff | 暂停读取一个工作区 Diff，确认可先打开另一文件。在预览请求等待时继续编辑旧 Diff，并更新新文件的暂存基准。切换前应保存旧文件，打开后应显示最新基准。Agent 同时修改旧文件时应显示保存冲突。取消切换或重新预览该文件后，磁盘版本和未保存草稿都应保留。 |
| 34 | 后台恢复审阅历史 | 分别暂停「返回」打开工作区 Diff、提交 Diff 及「最近位置」打开提交 Diff 的读取。切到另一标签后，迟到的结果不能切回旧页面，历史项仍可重试。模拟暂时的 Git 读取错误，确认「返回」仍指向原位置，成功后「前进」回到出发标签。 |
| 35 | 仓库版本与工作区标签 | 对同一路径分别打开提交版本和工作区文件。用返回、前进以及最近位置重开已关闭的只读标签，核对提交哈希和内容。让 Git 读取暂停或报错，确认可以继续切标签并重试。工作区已改名的文件也应能按旧路径打开历史版本。 |
| 36 | 从失效入口打开本地源码 | 固定一个搜索结果后打开同一文件的 Project 菜单，再把文件移走。从旧菜单预览、从搜索结果打开，均应保留当前编辑器并提示旧路径失效。Project 可打开新路径。删除 Diff 的 F4 应保留当前 Diff，并提示本地文件已不存在。 |
| 37 | 已打开文件被改写或移走 | 改写干净文件，确认内容自动更新。移走后，原标签保留最后一次读到的内容供复制。恢复原路径后内容与提示随磁盘更新。对未保存草稿重复外部改写和移走，确认有明确提示且草稿仍可复制。在删除冲突弹窗打开后让目录占用原路径，确认弹窗保留草稿并提示无法核对。 |
| 38 | 工作区 Diff 中的磁盘状态 | 将 Diff 正在比较的文件替换为目录，确认原差异可继续查看并提示暂不可读。移走目录后，右侧应显示真实的文件删除。恢复文件后提示消失。编辑右侧后从外部改写并移走文件，确认草稿保留，保存时可复制草稿，原路径保持空缺。 |
| 39 | Git 比较基准与三栏审阅 | 让 Git 无法读取已存在的索引对象。首次打开 Diff 应显示错误。已打开的 Diff 应保留两侧原内容、提示基准暂不可读并暂停按块操作。恢复 Git 对象并刷新后继续审阅。三栏审阅应区分被目录占用的路径与真正删除的工作区文件。另检查首个提交前的暂存、新增意向和已暂存删除。 |
| 40 | 非文本暂存版本与工作区草稿 | 编辑右侧时，将暂存版本换成二进制文件或超过 2 MiB 的文件。确认左侧标为上次有效版本，右侧草稿可在单栏和双栏查看，增删计数和按块操作暂停。恢复文本基准后重新显示差异。在非文本基准下保存只写工作区，撤销全部草稿则返回正常的无法比较提示。 |
| 41 | 切换焦点后的首个快捷键 | 从 Commit 变更行按一次 `⌘D` 打开 Diff。在提交 Diff 间连续用 `⌘[` 和 `⌘]` 往返，每次只按一次。Diff 聚焦后按 `⌘⇧O` 打开文件选择器。选择器打开时按 `⌘[` 应保持原 Diff，关闭后导航恢复。按原生事件记录核对快捷键匹配与命令分发。 |
| 42 | Diff 归属提示的坐标与缓存 | 提示显示前拖动滚动条或按 Page Down，旧提示应取消。编辑右侧有历史归属的行后重新悬停，应显示本地修改。暂停一次 Git 归属读取，滚动并切换文件，恢复请求后确认当前提示仍对应新文件。 |
| 43 | 文件内容相同但 HEAD 不同 | 在工作区 Diff 和源码 Git Blame 中查看同一行。外部将 HEAD 指向文件树相同、作者和历史不同的提交。确认 Diff 旧提示消失，重新悬停及源码侧栏显示新作者。核对工作区字节和暂存对象保持一致。 |
| 44 | 独立打开 linked worktree | 将工作树单独打开，主仓库置于工作区外。只从外部改暂存区，确认已打开的工作区 Diff 更新左侧。只更新当前分支的共享引用，再让工作树切到另一历史的分离 HEAD，确认每次重新悬停都显示对应作者。核对两次 HEAD 变化前后的文件字节和暂存对象。 |
| 45 | 暂存区切换中的 Diff 工具栏 | 切换到暂存区，延迟一次 Git 读取。在布局按钮上按住鼠标，等暂存比较加载后再松手，确认一次点击即可切换栏位，显示的仍是 HEAD 与暂存区的比较。工作区文件和暂存对象保持一致。 |
| 46 | 切换 Diff 栏位时的视野 | 打开文件后段的改动并跳到第二处，在单栏和双栏之间来回切换，确认改动和计数仍可见。拖动未聚焦一侧的滚动条后切换，确认新布局显示刚读到的上下文。在工作区 Diff、提交 Diff 和折叠未改动行的场景复测。 |
| 47 | 外部 Git 操作后的记录刷新 | 打开 Git 记录并设置搜索筛选。分别从外部创建提交、新建分支和标签。原子替换 `packed-refs` 来新增和移除标签，确认两次都刷新装饰并保留所选文件和已打开的 Diff。将所选提交从所有引用中移除，确认右侧选中当前可见提交，已打开的 Diff 继续比较原版本。从源码打开文件历史后提交新的文件改动，并与「查看截至此处的历史」复测两个入口。 |
| 48 | 工作区 Diff 的撤销与重做 | 在双栏右侧修改文件，切到单栏再返回双栏，用 `⌘Z` 和 `⇧⌘Z` 检查草稿。跳到源码并返回后复测撤销。再切到另一个 Diff，确认撤销和重做不会带入此前的编辑。分别在单栏和双栏打开干净的 Diff，让外部程序改写文件，核对新内容与磁盘字节。 |
| 49 | 文件间切换后的 Diff 撤销 | 编辑第一个工作区 Diff，打开第二个确认触发受检保存。用变更列表或 `⌘[` 返回第一个文件，验证 `⌘Z` 和 `⇧⌘Z`。撤销后核对磁盘仍是上次保存的版本，再保存并核对内容。用字节相同的新文件替换暂时离开的文件，确认返回后不恢复旧文件的撤销记录。 |
| 50 | 格式化和本地历史恢复的撤销 | 编辑工作区 Diff，分别从单栏和双栏通过自动格式化保存。在双栏撤销格式化、再撤销原编辑，然后依次重做。通过「查找操作」打开本地历史，分别恢复单个变更块和完整快照。确认弹窗内按 `⌘Z` 和 `⌘S` 时背景草稿及磁盘保持原样，按 `Esc` 关闭后可撤销和重做。 |
| 51 | 工作区单栏 Diff 编辑 | 在单栏输入含 emoji 的文字并跨行粘贴，在单栏撤销，在双栏重做，再从单栏保存。核对文件字节、CRLF 和 Git 暂存对象。尝试编辑历史侧的行、跨越历史行粘贴，以及在暂存和提交 Diff 中输入。另用空文件验证首次输入和末尾换行后的光标。[IDEA Diff Viewer](https://www.jetbrains.com/help/idea/differences-viewer.html) |
| 52 | 源码和工作区 Diff 共用撤销 | 在源码和单栏 Diff 各做一次编辑，按 `F4` 回源码依次撤销，再回 Diff 直接按键重做。在两处分别测试「放弃更改」和保存冲突后的「使用磁盘版本」，确认同一份草稿已清除。用字节相同的新文件替换已保存文件，验证两处的旧撤销都失效。从 Diff 末尾空行按 `F4` 应落在源码同一空行。 |
| 53 | 单栏 Diff 行内高亮 | 在单栏和双栏比较包含中文、emoji 和同一词内修改的文件。对照「按词」「按字符」「关闭」三种选项。关闭后仍可看见新增或删除的整行。编辑单栏工作区文本后切换选项，核对光标、草稿、撤销和原始磁盘字节。 |

## 其余功能回归

Mac 有窗口验收使用 Crisp 的独立扩展虚拟屏。设置 `NEMOROUS_NATIVE_CRISP=1` 运行 `native_macos_window`，验收本地历史、工作区双栏 Diff 和提交历史单栏 Diff 的归属。使用包含不同作者和日期的提交验证首次悬停、滚轮收起提示、鼠标停留和移动后重新显示归属。单栏从删除行滚到新增行，分别核对父提交和所选提交的信息。加上 `NEMOROUS_NATIVE_LINKED_WORKTREE=1` 可复测关联工作树的 Diff 与源码撤销和重做。测试会核对显示器活动状态、窗口边界和键盘焦点，合成事件只送给测试窗口，窗口内的悬停也不会设置系统光标。其他可见验收也需要具备同样的隔离条件。

保留 `NEMOROUS_NATIVE_CRISP=1` 并设 `NEMOROUS_NATIVE_LEFT_TOOL_WIDTH=350` 或 `128`，可在同一块屏验收 Project、Commit 工具栏和文件列表的横向滚动。

Crisp 屏休眠时，可额外设置 `NEMOROUS_CRISP_OFFSCREEN_DIAGNOSTICS=1`，在始终隐藏的 AppKit 窗口里验证点击分发和滚动位置。可见验收使用活动的 Crisp 模式。
