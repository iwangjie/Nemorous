# 冲突解决工作台

Nemorous 的冲突解决不是“编辑 <<<<<<< 文本”，而是一个三栏 + 结果编辑器的合并工作台，覆盖 merge、rebase、cherry-pick、revert 与手动合并冲突。

## 布局

```
┌──────────────────────────── OURS ─────────────┬──────── RESULT ────────┬──────── THEIRS ────────────┐
│ 变基目标（上游）                               │ 合并结果（可直接编辑） │ 你的提交                    │
├───────────────────────────────────────────────┴────────────────────────┴────────────────────────────┤
│ 冲突 2/4  ‹ ›   采用 Ours   采用 Theirs   两者        自动合并   更多…   保存并标记解决              │
└──────────────────────────────────────────────────────────────────────────────────────────────────────┘
```

- 固定左中右三栏：左侧 **Ours**、中间 **Result**、右侧 **Theirs**，不再额外占用一栏显示 Base；需要 Base 时通过“更多…”中的“采用 Base 版本”使用。
- 三栏使用索引中的版本，带语法高亮、行号与当前冲突块高亮；导航冲突时三栏和结果编辑器同步滚动。
- 对 rebase 会明确标注 `Ours = 变基目标（上游）`、`Theirs = 你的提交`；cherry-pick/revert 与 merge 使用各自的语义标签。
- 顶部文件选择器显示当前文件与剩余冲突块数量；解决并暂存后自动载入下一个文件。
- 未保存的解决结果按文件保存在草稿中，切换文件、关闭再打开（同一仓库）都不会丢失；关闭有草稿的工作台会二次确认。

## 解决方式

| 操作 | 说明 |
| --- | --- |
| 采用 Ours / Theirs | 只替换当前冲突块 |
| 两者 / Theirs→Ours | 拼接双方，顺序可选 |
| 采用 Base | 恢复到共同祖先版本（有 diff3 Base 时） |
| 自动合并 | 安全地合并双方不重叠的行修改；重叠部分保留冲突，并报告解决/剩余数量 |
| 整文件… | 全部采用某一侧、使用索引版本、重新解析冲突块 |
| 删除文件 | 删除/修改冲突中明确保留删除的一侧 |
| 保存并标记解决 | 校验不再有冲突标记，写回并 `git add`；结果为空时执行 `git rm` |

自动合并按行做三方比较：同一冲突块内双方修改的是 Base 的不同行时自动合并；相同修改只保留一份；任何重叠或相邻歧义都保留冲突，不会猜测。可随时“撤销自动解决”。

二进制冲突不会进入文本编辑器：提供“保留 Ours / 采用 Theirs / 删除文件”，按原始字节写回。

CRLF/LF 行尾会保留，不会因为解决冲突而重写整个文件。

## 快捷键

| 快捷键 | 动作 |
| --- | --- |
| `⌥←` / `⌥→` | 上一个 / 下一个冲突块 |
| `⌥1` / `⌥2` / `⌥3` | 采用 Ours / Theirs / 两者 |
| `⌘S` | 保存并标记解决 |
| `⌘⏎` | 所有文件解决后继续 Rebase/Cherry-pick/Revert/合并 |
| `Esc` | 关闭（有未保存结果时确认） |

## 结束操作

- rebase/cherry-pick/revert：全部冲突暂存后点击「继续 Rebase / Continue Cherry-pick / Continue Revert」；也可在 Git 高级操作中中止。
- 手动合并：解决完成后回到合并视图点击「完成并推送」或「完成（本地）」。
- 普通合并：解决后点击「完成合并」。

所有继续/中止操作都使用 Git 自身状态，不会伪造提交；手动合并的完成仍走既有的 6 层机器校验流程。
